# ModelOps AI — API documentation

Base path: **`/api/v1`**. Interactive OpenAPI docs are served at **`/api/docs`** (schema at `/api/openapi.json`).

## Conventions

### Authentication

| Used by | Mechanism |
| --- | --- |
| Management API (everything except the gateway, health and auth entry points) | `Authorization: Bearer <access_token>` — a 15-minute JWT returned by login/register/refresh |
| Session renewal | `modelops_rt` httpOnly cookie (path `/api/v1/auth`), set by login/register/refresh |
| Gateway (`/gateway/*`) | A **project API key** (`mk_…`) in `Authorization: Bearer`, `x-api-key` or `x-goog-api-key` |

Access tokens are not gateway keys and project keys are not access tokens — each is rejected where the other is expected.

### Errors

Every error generated by ModelOps uses the same shape and includes the request ID (also returned in the
`X-Request-ID` header):

```json
{ "error": { "code": "not_found", "message": "Project not found", "request_id": "req_6f1c0e2b9d8a4c55a1b2c3d4" } }
```

Validation errors (`422`) add `details: [{ "loc": ["body", "name"], "msg": "Field required" }]` — submitted values are
never echoed back. Resources owned by another user return `404`, never `403`, so existence is not revealed.

| Status | Typical codes |
| --- | --- |
| 400 | `invalid_request`, `provider_not_configured`, `invalid_password`, `confirmation_required`, `limit_reached` |
| 401 | `unauthorized`, `invalid_token`, `invalid_credentials`, `invalid_project_key`, `session_expired`, `session_revoked` |
| 402 | `budget_exceeded` (gateway, enforced budget) |
| 403 | `provider_not_allowed` (gateway) |
| 404 | `not_found`, `unsupported_endpoint` |
| 409 | `email_taken`, `name_taken`, `duplicate` |
| 413 | `payload_too_large` |
| 422 | `validation_error` |
| 423 | `account_locked` |
| 429 | `rate_limited` (with `Retry-After`) |
| 502 / 504 | `provider_unreachable`, `invalid_provider_response`, `provider_timeout`, `analyst_*` |
| 503 | `analyst_not_configured`; `/health` when the database is unavailable |

### Rate limits (per process, per minute; configurable)

Login: 10 per e-mail and 50 per IP · Register: 10 per IP · Management API: 300 per user · Gateway: 120 per project key (and 600 per IP) ·
Token refresh: 60 per IP · Password change: 5 per user · Provider key changes: 20 per user · AI Analyst: 10 per user.

### Dates and money

Timestamps are ISO-8601 UTC. Monetary values in request/pricing records are decimal strings (`"0.00045000"`);
aggregate analytics values are JSON numbers. All costs are **estimates**.

## Authentication & account

### `POST /auth/register` → 201

```json
{ "email": "ada@example.com", "password": "Correct-Horse-9", "full_name": "Ada Lovelace" }
```

Password policy: 10–128 characters with at least three of lowercase, uppercase, digit, symbol.
Response (also sets the refresh cookie):

```json
{
  "access_token": "eyJhbGciOi...",
  "token_type": "bearer",
  "expires_in": 900,
  "user": {
    "id": "0b6c0c7e-3f7e-4f3e-9a51-2d8a7b8f1c11", "email": "ada@example.com", "full_name": "Ada Lovelace",
    "created_at": "2026-11-15T10:00:00Z", "last_login_at": "2026-11-15T10:00:00Z", "password_changed_at": "2026-11-15T10:00:00Z"
  }
}
```

### `POST /auth/login` → 200

`{"email": "...", "password": "..."}` → same response as register. Five consecutive failures lock the account for
15 minutes (`423 account_locked`). Unknown e-mail and wrong password return the same `401 invalid_credentials`.

### `POST /auth/refresh` → 200

No body; uses the `modelops_rt` cookie. Rotates the refresh token and returns a new access token. Replaying a rotated
token outside a 20-second grace window (for concurrent tabs) revokes **all** of the user's sessions (`401 session_revoked`).

### `POST /auth/logout` → 204

Revokes the current refresh token and clears the cookie.

## Gateway

All gateway endpoints accept the provider's native request body (unknown fields are forwarded unchanged), return the
provider's native response and status code, and add `x-modelops-request-id`. Provider `Retry-After` and request
rate-limit headers are passed through.

| Method | Path | Provider endpoint |
| --- | --- | --- |
| POST | `/gateway/openai/chat/completions` (also `/gateway/openai/v1/chat/completions`) | OpenAI `POST /v1/chat/completions` |
| POST | `/gateway/anthropic/messages` (also `/gateway/anthropic/v1/messages`) | Anthropic `POST /v1/messages` (`anthropic-beta` header forwarded) |
| POST | `/gateway/gemini/generate` | Gemini `models/{model}:generateContent` — `model` and optional `stream` in the body |
| POST | `/gateway/gemini/v1beta/models/{model}:generateContent` | Native Gemini path (also `:streamGenerateContent`, always SSE) |

Required fields validated by the gateway: OpenAI `model` + non-empty `messages`; Anthropic `model` + `messages` +
`max_tokens`; Gemini `model` (generate endpoint) + non-empty `contents`.

### Example — OpenAI

```bash
curl https://HOST/api/v1/gateway/openai/chat/completions \
  -H "Authorization: Bearer mk_..." -H "Content-Type: application/json" \
  -d '{"model":"gpt-4o-mini","messages":[{"role":"user","content":"Hello"}]}'
```

Response: OpenAI's JSON exactly as returned (`id`, `choices`, `usage`, …) plus header `x-modelops-request-id: req_…`.

### Example — Anthropic (streaming)

```bash
curl -N https://HOST/api/v1/gateway/anthropic/messages \
  -H "x-api-key: mk_..." -H "Content-Type: application/json" \
  -d '{"model":"claude-haiku-4-5","max_tokens":256,"stream":true,"messages":[{"role":"user","content":"Hi"}]}'
```

The SSE stream is relayed byte-for-byte; usage is read from `message_start` / `message_delta` events.

### Example — Gemini

```bash
curl https://HOST/api/v1/gateway/gemini/generate \
  -H "Authorization: Bearer mk_..." -H "Content-Type: application/json" \
  -d '{"model":"gemini-2.5-flash","contents":[{"role":"user","parts":[{"text":"Hello"}]}]}'
```

### Usage capture

| Provider | Input tokens | Output tokens | Streaming |
| --- | --- | --- | --- |
| OpenAI | `usage.prompt_tokens` | `usage.completion_tokens` | Gateway sets `stream_options.include_usage=true`; usage read from the final chunk |
| Anthropic | `input_tokens + cache_creation_input_tokens + cache_read_input_tokens` | `output_tokens` | `message_start` + `message_delta` |
| Gemini | `usageMetadata.promptTokenCount` | `candidatesTokenCount + thoughtsTokenCount` | latest `usageMetadata` in the SSE stream |

### Gateway-generated errors (recorded as failed requests)

```json
{ "error": { "code": "provider_not_configured", "message": "No OpenAI API key is configured for this account.", "request_id": "req_…" } }
```

`400 invalid_request` · `400 provider_not_configured` · `403 provider_not_allowed` · `402 budget_exceeded` ·
`502 provider_unreachable` · `502 invalid_provider_response` · `504 provider_timeout`. Upstream errors (e.g. OpenAI
`401` or `429`) are returned unchanged and recorded with types `invalid_credentials`, `rate_limited`, `bad_request`,
`not_found` or `provider_error`. An upstream `401/403` also marks the stored credential as `invalid`.

## Analytics

### `GET /analytics/overview`

Query: `range` = `24h|7d|30d|90d|custom` (default `7d`); `start`, `end` (ISO-8601, required for `custom`, max 366 days);
optional `project_id`, `provider`, `model`. Granularity is hourly for spans ≤ 48 h, otherwise daily (UTC).

```json
{
  "range": { "start": "2026-11-08T10:00:00+00:00", "end": "2026-11-15T10:00:00+00:00", "granularity": "day" },
  "summary": {
    "current":  { "total_requests": 60, "successful_requests": 57, "failed_requests": 3, "error_rate": 5.0,
                  "input_tokens": 95803, "output_tokens": 25913, "total_tokens": 121716,
                  "estimated_cost_usd": 0.276461, "avg_latency_ms": 228.6, "unpriced_requests": 0 },
    "previous": { "total_requests": 0, "...": "same fields for the preceding period of equal length" }
  },
  "timeseries": [ { "bucket": "2026-11-15T00:00:00+00:00", "requests": 60, "errors": 3, "error_rate": 5.0,
                    "input_tokens": 95803, "output_tokens": 25913, "cost_usd": 0.276461, "avg_latency_ms": 228.6 } ],
  "by_provider": [ { "provider": "anthropic", "requests": 18, "errors": 0, "error_rate": 0.0, "input_tokens": 0,
                     "output_tokens": 0, "total_tokens": 0, "estimated_cost_usd": 0.21, "avg_latency_ms": 183.0,
                     "unpriced_requests": 0, "request_share": 30.0, "cost_share": 75.9 } ],
  "by_model":   [ { "provider": "anthropic", "model": "claude-sonnet-4-5", "...": "same metrics" } ],
  "by_project": [ { "project_id": "…", "project_name": "Support Bot", "...": "same metrics" } ]
}
```

### `GET /analytics/costs`

Same range/project parameters (default `30d`). Returns `total_usd`, `previous_total_usd`, `unpriced_requests`, `trend`,
`by_provider`, `by_model`, `by_project` and `summaries` = `{ daily: [30 days], monthly: [up to 12 months], today_usd, month_to_date_usd }`.

## Request logs

### `GET /requests`

Query: `q` (request ID, model or error text), `provider`, `status` (`success|error`), `project_id`, `model`, `start`,
`end`, `sort` (`created_at|latency_ms|cost|total_tokens|input_tokens|output_tokens`), `order` (`asc|desc`),
`page` (≥ 1), `page_size` (1–100, default 25).

```json
{
  "items": [{
    "id": "…", "request_id": "req_9bc179be3d2c8258bd6c1673", "created_at": "2026-11-15T13:23:49Z",
    "provider": "openai", "model": "gpt-4o", "endpoint": "chat.completions", "project_id": "…",
    "project_name": "Weather AI Assistant", "streamed": false, "status": "error", "http_status": 500,
    "error_type": "provider_error", "error_message": "upstream overloaded", "input_tokens": 0, "output_tokens": 0,
    "total_tokens": 0, "latency_ms": 233, "cost_total_usd": "0.00000000", "cost_status": "estimated"
  }],
  "total": 3, "page": 1, "page_size": 25
}
```

### `GET /requests/{request_ref}`

By UUID or `req_…` ID. Adds `cost_input_usd`, `cost_output_usd`, `pricing_model_key`, `input_price_per_mtok`,
`output_price_per_mtok`, `pricing_verified` (the pricing snapshot) and `api_key_id`.

### `GET /requests/models` — distinct model names seen in the account.

## Pricing

| Method | Path | Notes |
| --- | --- | --- |
| GET | `/pricing?provider=openai` | Reference catalogue (`scope: "catalog"`) + your overrides (`scope: "custom"`) |
| POST | `/pricing` | `{"provider":"openai","model":"gpt-4o","input_price_per_mtok":"2.5","output_price_per_mtok":"10","verified":true,"notes":"…"}` → 201 |
| PATCH | `/pricing/{id}` | Custom entries only: `input_price_per_mtok`, `output_price_per_mtok`, `verified`, `notes` |
| DELETE | `/pricing/{id}` | Custom entries only (catalogue entries return 404) |
| GET | `/pricing/preview?provider=&model=&input_tokens=&output_tokens=` | Which entry matches and the resulting estimate |

Matching: your override beats the catalogue; an exact model name beats a version-suffix match (`gpt-4o` covers
`gpt-4o-2024-08-06`, never `gpt-4o-mini`). No match → `cost_status: "unknown"` and a `null` cost.
